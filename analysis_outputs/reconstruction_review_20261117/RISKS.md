# 风险与建议顺序

1. **先补 Python 配置校验（F1）。** 防止看似开启重建，实际始终没有候选。把必需关系集中在模型/训练入口；不要修改用户选择的预算、阈值或算法。
2. **补拒绝证据（F3）。** 失败报告传递部件对、深度、阈值和分支步数。信息来自已有计算，不需要额外碰撞查询。
3. **补 controller 的 CPU 协作回归，再集中分支清理（F4）。** 现有局部测试不能证明所有状态组合都正确；本轮也没有复现 controller 状态不一致。
4. **对实际需要使用的可选路径消除动态压缩（F2）。** 默认 dreamer + 独立 decoder 路径不受本轮指出的这两处影响。需要使用 R2 或联合物理梯度时，再验证整条编译路径；本轮不能量化 GPU 影响。

不建议为减少代码行数而删除事务 replay、普通 cached latent、float64 标签边界或分支预算，也不建议重新引入同来源限制、被过滤几何对检查或第五步以后的穿模检查。它们分别受数据契约和用户明确要求约束。

本轮发现范围是实现与维护性。未验证 learned decoder 在正式训练中的物理精度、恢复接受率、探索收益，也没有通过启动新训练补这些证据。
